# Optimization SDK

`picpp-opt` is the offline side of pi.cpp. It inspects and rewrites portable
ONNX assets, builds target-local TensorRT engines, and emits machine-readable
evidence. It is not imported by the C++ runtime, `picpp`, or `picpp-tui`.

Install the optional graph dependencies:

```bash
uv pip install -e ".[optimization]"
```

TensorRT commands call the `trtexec` installed on the target. TensorRT engines
remain local because their tactics and ABI depend on the GPU and TensorRT
version.

## FastWAM AGX Workflow

The public recipe is
`recipes/fastwam/agx-orin-int8.json`. It describes the four-stage context K/V
cache contract and keeps five sensitive action-boundary nodes in FP16:

```text
time_embedding.0
time_embedding.2
time_projection.1
action_encoder
head
```

The recorded published asset passed `375/400` AGX LIBERO episodes. The recipe
itself remains `measured` until a graph generated by this SDK either matches
the accepted portable artifact identity or passes a fresh target-hardware
promotion ladder.

Set paths for a fresh candidate workspace:

```bash
export FASTWAM_FP=/path/to/fastwam_fp16/onnx
export CANDIDATE=/path/to/fresh/fastwam_int8_candidate
mkdir -p "$CANDIDATE/onnx" "$CANDIDATE/evidence" "$CANDIDATE/engines"
```

Inspect the source stages:

```bash
for stage in video_prefill context_kv_prefill action_step_dynamic_kv; do
  picpp-opt inspect \
    --onnx "$FASTWAM_FP/$stage.onnx" \
    --output "$CANDIDATE/evidence/$stage.fp.inspect.json"
done
```

Generate selective QDQ ONNX. Large stages should use a relative external-data
filename so the ONNX and weights remain portable as one directory.

```bash
for stage in video_prefill context_kv_prefill action_step_dynamic_kv; do
  picpp-opt qdq \
    --source-onnx "$FASTWAM_FP/$stage.onnx" \
    --output-onnx "$CANDIDATE/onnx/$stage.onnx" \
    --external-data-file "$stage.data" \
    --recipe recipes/fastwam/agx-orin-int8.json \
    --stage "$stage" \
    --summary "$CANDIDATE/evidence/$stage.qdq.json"
done
```

`rollback` regenerates from the FP source and adds precision guards. It does
not pretend that pre-quantized INT8 weight initializers can recover discarded
floating-point bytes.

```bash
picpp-opt rollback \
  --source-onnx "$FASTWAM_FP/action_step_dynamic_kv.onnx" \
  --output-onnx "$CANDIDATE/onnx/action_step_guarded.onnx" \
  --external-data-file action_step_guarded.data \
  --recipe recipes/fastwam/agx-orin-int8.json \
  --stage action_step_dynamic_kv \
  --keep-fp16 'blocks[/.]17' \
  --summary "$CANDIDATE/evidence/action_step_guarded.qdq.json"
```

Compare FP and QDQ ONNX outputs on the same input bundle:

```bash
picpp-opt compare \
  --reference-onnx "$FASTWAM_FP/action_step_dynamic_kv.onnx" \
  --candidate-onnx "$CANDIDATE/onnx/action_step_dynamic_kv.onnx" \
  --inputs-npz /path/to/action_step_inputs.npz \
  --provider CUDAExecutionProvider \
  --output "$CANDIDATE/evidence/action_step.compare.json"
```

The comparison reports shape, finite status, max absolute error, L2, relative
L2, cosine similarity, and SQNR for every output.

## TensorRT Evidence

Build each engine on the target GPU. Shape JSON maps dynamic input names to one
concrete shape, for example `{"tokens": [1, 129, 1024]}`.

```bash
picpp-opt trt-build \
  --onnx "$CANDIDATE/onnx/action_step_dynamic_kv.onnx" \
  --engine "$CANDIDATE/engines/action_step_dynamic_kv.engine" \
  --shapes-json /path/to/action_shapes.json \
  --fp16 --int8 --detailed \
  --target-name agx-orin --architecture ampere-sm87 \
  --layer-info "$CANDIDATE/evidence/action.layers.json" \
  --log "$CANDIDATE/evidence/action.build.log" \
  --output "$CANDIDATE/evidence/action.build.json"
```

Inspect and benchmark one stage:

```bash
picpp-opt trt-inspect \
  --engine "$CANDIDATE/engines/action_step_dynamic_kv.engine" \
  --shapes-json /path/to/action_shapes.json \
  --target-name agx-orin --architecture ampere-sm87 \
  --layer-info "$CANDIDATE/evidence/action.inspect.layers.json" \
  --log "$CANDIDATE/evidence/action.inspect.log" \
  --output "$CANDIDATE/evidence/action.inspect.json"

picpp-opt trt-bench \
  --engine "$CANDIDATE/engines/action_step_dynamic_kv.engine" \
  --shapes-json /path/to/action_shapes.json \
  --warmup-ms 1000 --repeats 100 \
  --target-name agx-orin --architecture ampere-sm87 \
  --times "$CANDIDATE/evidence/action.times.json" \
  --profile "$CANDIDATE/evidence/action.profile.json" \
  --log "$CANDIDATE/evidence/action.bench.log" \
  --output "$CANDIDATE/evidence/action.bench.json"
```

Stage timing uses `trtexec --noDataTransfers` and a separate profiler run. It
excludes H2D/D2H, preprocessing, stage handoff, the ten-step policy loop,
server/client transport, and closed-loop simulation. Those measurements must
remain separate. Target evidence records the hardware fingerprint, CUDA and
TensorRT versions, warmup, requested iterations, and timing boundary; an
unavailable CUDA version is represented explicitly rather than inferred. A new
asset is not `accepted` until artifact identity carries existing evidence or
the full mechanical, parity, standalone, server/client, and LIBERO 400 ladder
passes.
